# Page-building principles

## Begin with the user task

Make the main reason for visiting the page clear near the top. Organisational background should not displace the action or information most visitors need.

## Establish a clear hierarchy

Use one descriptive page heading. Give each section a meaningful heading and keep heading levels in order. Avoid headings that describe the layout rather than the content.

## Make actions explicit

Use descriptive link and button text. Say what the visitor will get or what happens next; avoid “click here”, “read more” and repeated “here” links.

## Use components for their intended job

Choose a component because its behaviour and semantics suit the content. Do not use cards, accordions or tabs simply to make a page look more designed.

## Design for small screens

Rows, columns, cards, tables and images must reflow into a usable mobile layout. Never depend on three narrow columns or horizontal scrolling to make essential content understandable.

## Keep pages economical

Prioritise, group and remove. Repetition, decorative imagery and too many calls to action make the important content harder to find.

## Build accessibly

Provide useful alternative text where an image conveys information, label controls clearly, use real lists and headings, maintain colour contrast and ensure the reading order makes sense without the visual layout.

## Treat templates as governed patterns

Each template should have an owner, a defined user need, evidence or rationale, and a review date. Test patterns with editors and end users before treating them as established.
