# Contributing

## Before adding a pattern

Confirm that it solves a recurring user or editor need and that an existing component, section template or page template does not already cover it.

## Minimum evidence

A proposal should include at least one source of evidence, such as user research, usability testing, analytics, support requests, content audits or repeated migration needs.

## Review checklist

- The pattern has one clear purpose.
- The CMS component names are accurate.
- Content rules are specific enough to guide editors.
- Responsive behaviour has been checked.
- Accessibility requirements are documented and tested.
- The example uses realistic content.
- Ownership and review status are recorded.
- The pattern does not duplicate an existing option.

## Suggested lifecycle

**Draft → Tested → Approved → Reviewed → Retired**

Changes to approved patterns should explain what changed and why.
